# 잇다 — 끝말잇기

말을 이어가는 5단계 봇과의 1:1 끝말잇기. 732,308 단어 사전, 표준 두음법칙, 5단계 난이도.

- 라이브: **https://itda-play.pages.dev** (Cloudflare Pages, `main` 푸시하면 자동 배포)
- 이전 주소: https://itda-play.onrender.com (같은 저장소의 Render Static Site — 계정 기능은 Pages 에만 있다)
- 저장소: https://github.com/Eomukim/itda

## 규칙

- 2글자 이상이면서 한글로 시작해 한글로 끝나는 단어만. 중간의 숫자·영문자는 그대로 쓴다(`가락1동`, `…17년전으로돌`). 이미 나온 단어는 다시 쓸 수 없다.
- **첫 제시 글자(끄투식)** — 대국은 아무 단어나 치는 게 아니라, 사전의 **2~3글자 일상 단어(제시어)** 에서 뽑은 첫 글자로 시작한다.
  제시어는 모든 글자가 다음 단어로 이어지고(한방 글자 없음), 그 첫 글자로 일상 단어가 20개(Lv.1·2) 이상 이어지는 것만 쓴다.
  화면에는 `‘사’로 시작하는 단어를 입력하세요`와 `이어야 할 글자`로 그 글자만 보여 준다(제시어 자체는 숨긴다).
  봇 선공(Lv.1~4)도 같은 글자에서 봇이 먼저 두고, Lv.5 지옥의 선공 오프닝은 그대로 유지된다.
- 앞 단어의 끝 글자로 시작해야 하며, 두음법칙 변환 글자도 인정된다(`력` → `역`).
- 자기 차례 제한 시간(1초 또는 5~50초 5초 단위, 기본 15초)을 넘기면 패배. 이을 단어가 없으면 그 자리에서 패배.
- 점수 = (글자수² + 글자수×4) × 콤보 배수(최대 2.5) × 미션 배수.
- 미션 글자는 가·나·다·라·마·바·사·아·자·차·카·타·파·하 14종 중 하나로 시작한다. 단어에 1번 들면 +50%, 2번 겹치면 ×2, 3번이면 ×3으로 중첩된다(`미션 ×2` 표시).
- 미션 글자는 성공(미션 글자가 든 단어 입력) 전까지 그대로 유지되고, 나나 봇이 성공하는 순간 직전과 다른 다음 미션 글자로 바뀐다.

## 단어 사전

설정 화면 **맨 위 오른쪽 `📖 사전`** 버튼으로 연다. 대전 중 막혔을 때, 또는 어떤 글자로 시작하는 단어가 얼마나 강한지 미리 볼 때 쓴다.

- **검색** — 첫 글자(예: `리`)를 넣으면 그 글자로 시작하는 단어, 2글자 이상(예: `가방`)은 그 앞부분으로 시작하는 단어를 찾는다. 숫자·영문자가 섞인 표제어도 그대로 찾고(`가락1동`), 71글자 장문(`너바나더밴드…17년전으로돌`)도 통째로 붙여넣을 수 있다(검색어 상한 80자).
- **두음 포함** — 켜면 두음법칙 대체 글자까지 함께 본다(`리` → `이` 단어도, `라면` → `나면…`도). 끄면 정확히 넣은 글자로 시작하는 단어만. 두음으로 걸린 단어에는 `두음` 표시가 붙는다.
- **정렬 4종**
  - `어려움순` — 한방 단어(끝 글자의 후속 0개)가 맨 위, 그다음 후속 단어가 적은 공격 단어 순(후속 수 오름차순).
  - `쉬움순` — 일상 명사(국립국어원 학습용·TOPIK 목록) 먼저, 그다음 후속 단어가 많은(이어가기 쉬운) 순.
  - `긴순` / `짧은순` — 글자 수 내림/오름차순.
- **항목** — 단어, 글자 수, 끝 글자 후속 배지(`🔥 한방` 또는 `후속 N개`), `일상`·`외래어`·`두음` 표시.
- **단어를 누르면 복사** — 목록의 단어를 누르면 그 단어가 클립보드로 들어가고 `‘가방’ 복사됨` 토스트와 짧은 소리로 알려 준다(클립보드 API가 막힌 곳은 옛 `execCommand('copy')`로 한 번 더 시도). 복사는 검색어·목록·정렬을 건드리지 않는다.
- **`후속 N개`를 누르면 그 글자로 이어서 찾기** — 단어의 끝 글자를 검색어로 넣고 그대로 다시 검색한다. 지금 고른 `정렬 4종`과 `두음 포함`이 그대로 적용되고, 목록은 맨 위부터 보여 준다. 후속 단어를 타고 계속 내려가다가 `← 이전` 칩으로 직전 검색어로 한 단계씩 돌아올 수 있다(직접 검색어를 치면 기록은 초기화). `🔥 한방`은 후속이 0개라 누를 수 없다.
- **성능** — 결과가 1만 개를 넘어도(`이` 9,513개) 한 번에 100개만 그리고 `더 보기 (N개 남음)`으로 이어서 불러온다. 검색은 시작 음절 구간의 이진 탐색이라 9,513개짜리 글자도 20ms 안쪽이고, 정렬은 끝 글자별로 후속 수를 한 번만 계산해 쓴다.
- **레이아웃** — 데스크톱 1280×800 · 모바일 390×844 · 360×640 모두 가로 오버플로 0, 키보드가 올라와 화면이 줄어도 검색창·정렬·목록이 남는다. 사전 화면이 열려 있어도 설정 화면의 정리 규칙(`대전 시작`이 마지막 요소 · 세로 스크롤 0)은 그대로다.

## 설정 (⚙ 설정)

설정 화면 오른쪽 위 **`⚙ 설정`** 버튼을 누르면 별도 창이 열린다. 홈 화면에 있던 `효과음 켬/끔` 행은 여기로 옮겼다.

- **음량** — `0% ~ 100%` 슬라이더. 값에 비례해 효과음 크기(master gain)가 바뀌고 0%면 완전히 무음이다.
  아이콘을 누르면 음소거/해제되고, 해제하면 직전 음량으로 돌아온다. 슬라이더에서 손을 떼면 그 음량으로 짧은 시험음이 난다.
  예전 버전에서 `효과음 끔`으로 저장한 사용자는 `0%`로 그대로 이어진다.
- **흑백모드** — 스위치를 켜면 배경·보드·사전·결과 시트·토스트까지 화면 전체가 흑백이 된다.
  `html`에 클래스 하나만 붙여 `.bg`·`#app`·`.overlay`에 `filter: grayscale(1)`을 거는 방식이라 레이아웃과 뷰포트 계산은 그대로다.
- 두 값 모두 `itda.settings.v1`(`volume` · `monochrome`)에 저장되고, 화면을 다시 열어도 그대로 복원된다.

## 제한 시간

홈 화면의 **제한 시간** 칸은 `10·15·20초` 세 버튼 대신 **0~50초 눈금자 위의 슬라이더**다.

- 고를 수 있는 값은 **1초**와 **5~50초 5초 단위**(1·5·10·15·20·25·30·35·40·45·50)다.
- 슬라이더 트랙은 뚫지 않고, 트랙 바로 아래에 **0~50초 눈금자 11개**(0·5·10·…·50)를 따로 그렸다. 세 단계로 나뉜다.
  - **0·50** — 가장 굵고 길고 진한 눈금(2.5px × 13px, 진한 잉크) + 그 아래 `0초`·`50초` 숫자
  - **10의 배수**(10·20·30·40) — 그 다음으로 굵고 긴 눈금(2px × 9px, 중간 진하기)
  - **5의 배수**(5·15·25·35·45) — 가장 얇고 짧고 연한 눈금(1.5px × 5px, 연한 진하기)
- 눈금 자리는 썸이 움직이는 구간(양끝 썸 반지름만큼 안쪽)을 10등분한 지점이라, 5·10·…·50초에서 **썸 가운데·트랙 채움 끝·눈금이 0.1px 안**으로 겹친다. 네이티브 range는 `min=0 max=50 step=1`로 두어 썸 위치가 값/50과 같은 스케일을 쓴다.
- 드래그·클릭으로 0이나 2~4처럼 허용 밖 값이 들어오면 **가장 가까운 허용 값으로 즉시 스냅**한다(0·2 → 1초, 3·4 → 5초). 좌우(위아래) 화살표와 Home/End도 `1 ↔ 5 ↔ 10 ↔ … ↔ 50` 한 칸씩 움직이고, Home은 0이 아니라 최소 1초다.
- 라벨 옆 배지에 지금 고른 초가 또렷하게 보이고, 트랙 채움(`--pct` · `--ratio`)이 `값/50`으로 따라온다(1초 = 2%, 50초 = 100%, 채움은 썸 가운데까지).
- 1초·5~50초 값이 `timeLimit`으로 저장된다. 1초는 그대로 복원하고, 예전 버전이 1~50초 1초 단위로 남긴 `12`·`33` 같은 값은 가장 가까운 5초(10·35)로, `2`는 1초, `3`~`4`는 5초로 보정하며, 0 이하·51 이상·숫자가 아닌 값이 저장돼 있으면 기본 15초로 시작한다.
- 1초처럼 짧은 제한도 즉시 끝나지 않고 그 초만큼 세다가 시간 초과가 된다(엔진 마감 = `timeLimit × 1000`ms + 40ms 여유, 1초는 약 1.04초 뒤 종료).

## 배려모드

설정 화면의 **🛡️ 배려모드** 스위치를 켜면 대국 시작 후 **첫 5수(1~5수)** 동안 나와 봇 모두 한방 단어를 쓰지 않는다.

- **플레이어** — 한방 단어를 입력하면 `배려모드: 첫 5턴은 한방 단어를 쓸 수 없어요` 안내와 함께 거부되고,
  타이머는 계속 흐른다. 입력한 글자는 그대로 남아 있어 다른 단어로 바로 고칠 수 있다(콤보도 끊기지 않는다).
- **봇(Lv.1~5)** — 첫 5수 동안은 후속 단어가 남아 있는 수만 고른다. 사전에 후속 단어가 있어도
  이번 판에서 이미 다 써 버려 상대가 낼 수가 없는 글자(즉시 한방)도 피한다.
  5수째에 낼 수 있는 수가 전부 한방뿐이면 그 수를 두지 않고 막힌 것으로 처리한다.
- **6수부터** 보호가 풀려 정상적으로 한방 단어를 쓸 수 있다.
- **표시** — 대전 헤더의 `🛡️ 배려모드 (2/5턴 · 한방 금지)` 칩이 보호 중 몇 번째 수인지 보여 주고,
  6수째부터 `🛡️ 배려 해금`으로 바뀐다. 결과 화면에도 `🛡️ 배려모드` 배지가 붙는다.
- 상태는 `itda.settings.v1` 에 저장된다.

## 난이도

| 단계 | 봇의 행동 |
| --- | --- |
| Lv.1 쉬움 | 일상 명사(2~3글자)만, 끝 글자도 다음에 이을 일상 단어가 많은 쪽, 한방 단어 금지, 1.5~2.5초 응답 |
| Lv.2 보통 | 일상 명사(2~4글자) 위주, 가끔 4~6글자, 4턴 이후에만 낮은 확률로 짧고 일상적인 한방 |
| Lv.3 어려움 | 보통 말(75% 일상 명사 + 표준어 2~4글자)로 두면서 후속이 적은 글자로 조여 온다. 1~2수는 넉넉한 자리, 6수부터는 가끔 후속 1~4 자리를 골라 외통수, 10수 이후 낮은 확률로 한방. Lv.4·5처럼 3수 만에 끝나지 않는다 |
| Lv.4 극악 | 한방이 있으면 100% 즉시 사용(그 안에서도 보통 말 우선). 없으면 최소 후속 글자 근처(최소~+2)에서 매 판 다르게 골라 0.2~0.5초 압박 |
| Lv.5 지옥 | 루트전 그래프 + 실시간 수읽기. 한방 즉사 → 5~9수 강제 필승 → 위험한 수 전수 평가(독배) → 압박·미션. 상대가 낼 수 있는 **한방 단어는 그 자리의 단어 전수로 확인**해 절대 밟지 않고(예전에는 응수 96개만 봤다), 판단 예산은 한 수 90만 노드·0.7초. 같은 끝 글자 안에서는 보통 말을 먼저 고르고(장문 20~30자 어인정 표제어를 좇지 않는다), 매 수는 최상위권 후보 중에서 골라 같은 글자에도 단어가 겹치지 않는다. 0.15~0.4초. 봇 선공이면 이기는 시작 글자로 연다 |

봇 이름은 단계별로 잇다 주니어 · 잇다 루키 · 잇다 마스터 · 잇다 극악 · 잇다 지옥이다.

### Lv.5 지옥이 수를 읽는 방법

`build/build_data.py` 가 732,308단어의 음절 전이 그래프(표준 두음법칙 포함)를 역방향으로 분석해
`data/stats.json` 의 `graph` 에 남긴다. 노드는 '이어야 할 글자', 간선은 그 글자로 낼 수 있는 단어다.

- **승리(W)** = 지는 자리로 보낼 수 있는 글자, **패배(L)** = 모든 수가 이기는 자리로 이어지는 글자, **무승부(D)** = 둘 다 아닌 글자.
- 깊이는 완전한 대국에서 끝까지 걸리는 수. 빌드 때마다(월간 오픈DB 갱신 포함) 자동으로 다시 계산된다.
- 앱은 이 상태와 함께 **지금까지 나온 단어(`used`)** 를 반영해 실제로 검증한 수만 둔다.
  1. **한방 즉사**(상대 후속 0) — 어떤 한방이든 즉사이므로, 같은 끝 글자 안에서 보통 말(일상어 → 표준어 2~4글자 → 그 밖)을 먼저 고른다. 길이 점수는 6글자까지만 센다.
  2. **5~9수 강제 필승** — 내 수 → 상대 모든 응수 → 내 한방/필승을 하나하나 확인한다. 상대 응수가 1~2개로 좁아진 분기는 9수까지, 정적으로 패배(L)인 자리뿐 아니라 이미 나온 단어 때문에 새로 좁아진 함정 음절도 후보에 넣는다. 확인된 후보 중 가장 짧은 proof(=같은 깊이의 필승)를 가진 것들을 모아, 그중 상대 응수가 적은 쪽에서 고른다.
  3. **독배 평가** — 첫 안전 수에서 멈추지 않고, 시간 예산 안에서 안전 후보를 모두 뜯어본다(위험 수는 응수 96개 표본으로 점수를 매긴다). 상대가 무엇으로 받아쳐도 (즉사 한방 / 이기는 자리 / 무승부 / 지는 자리) 중 가장 나쁜 값이 최대가 되는 수, 즉 상대의 숨통이 가장 조여지는 수를 고른다. 상대 응수 하나로 봇이 막히는 수는 안전 후보에서 뺀다. 최고 등급(그래프 승리 상태) 안에서 독배 점수 4점 이내 후보 중에서 고른다.
  4. **압박·점수** — 상대 후보가 1~3개뿐인 글자로 몰고, 같은 조건에서는 미션·장문으로 점수를 챙긴다.
- **선공 오프닝**: Lv.5 에서 봇이 먼저 두면(`봇부터`) 아무 글자나 잡지 않고, 봇이 이기는 자리(W3·W5)의 시작 글자로 연다. 0수 한방으로 1초 만에 끝나는 자리는 피하고(깊이 3수 이상), 최단 깊이 하나로 고정하지 않고 최단 +2수(최대 7수) 안에서 골라 매 판 다른 글자로 시작한다.
- **매 판 다른 수**: 같은 글자·같은 자리에서 15번 두면 서로 다른 단어가 Lv.4 평균 6.2종 · Lv.5 평균 5.0종 나온다(한방이 하나뿐인 자리처럼 선택지가 1개인 국면은 제외). 승률·한방 각 차단 같은 강도 기준은 그대로다.
- 판단은 한 수당 평균 3ms 안쪽(보통 최대 40ms 이하, 상한 700ms), 응답 텀은 0.15~0.4초다.
- **상대 한방 전수 확인**: 어떤 수를 두기 전에, 그 끝 글자에서 상대가 낼 수 있는 한방 단어가 하나라도 있는지 그 자리의 단어를 끝까지 훑어 확인한다. 후속이 40개를 넘는 넓은 자리에서도 건너뛰지 않으며, 이번 판에서 시작 글자가 소진돼 새로 생긴 한방까지 찾는다. 1000판 벤치마크에서 피할 수 있었는데 상대 한방을 준 수는 0회다.

### 봇 대 봇 벤치마크

`tools/bench.mjs` 가 브라우저 없이 `js/` 의 사전·봇 코드를 그대로 불러와, 엔진과 같은 규칙으로
봇끼리 대국한다(레벨·선공·시작 글자 고정, 결정적 난수). 1000판씩 측정한 승률이다.

| 대국 | Lv.5 선공 | Lv.5 후공 |
| --- | --- | --- |
| vs Lv.4 극악 (500판, 전 시작 글자) | 98.4% | 24.8% |
| vs Lv.4 극악 (500판, 시작 글자에 한방 없음) | 96.4% | 59.6% |
| vs Lv.4 극악 (1000판, 후공이 이길 수 있는 D 등급 글자) | 90.5% | 98.2% |

후공 승률이 낮은 것은 봇이 약해서가 아니라 **판이 정해져 있어서**다. 시작 글자의 그래프 등급이
W면 그 글자로 먼저 두는 쪽(Lv.4)이 완전한 수로 이기고, 후공은 지는 자리를 받는다. 위 1000판
측정은 후공이 이길 수 있는(D 등급) 글자만 골라 둔 것이라, 그 자리에서 98.2%를 이긴다.
숨은 한방 감사(독립 구현)에서 **피할 수 있었는데 상대에게 한방을 준 수는 모든 측정에서 0회**다.
봇 선공 오프닝을 켜면 vs Lv.4 · vs Lv.3 모두 300판 전승(평균 3.4수 · 3.1수)이고,
오프닝 글자는 매 판 봇이 이기는 W등급에서 고른다.

```bash
/workspace/.local/node/bin/node tools/bench.mjs --games 1000 --levels 4,3,random --openings all
/workspace/.local/node/bin/node tools/bench.mjs --games 1000 --levels 4 --openings nokill --out downloads/bench.json
/workspace/.local/node/bin/node tools/bench.mjs --games 1000 --levels 4 --openings draw   # 후공이 이길 수 있는 글자만
/workspace/.local/node/bin/node tools/bench.mjs --games 500  --levels punish              # 숨은 한방을 바로 잡는 상대
```

## 계정 (로그인 · 회원가입)

게임은 로그인 없이 지금처럼 그대로 즐길 수 있고, 계정은 선택이다. 계정이 있으면 홈 오른쪽 위 맨 끝
`👤 로그인` 버튼이 내 아이디로 바뀌고, 누르면 가입 방식·가입일과 로그아웃·계정 삭제가 나온다.

| 방식 | 내용 |
| --- | --- |
| 아이디 + 비밀번호 | 이메일 없이 한글·영문·숫자·밑줄 2~12자 아이디와 6자 이상 비밀번호로 바로 가입/로그인 |
| 구글 로그인 | 구글 버튼 한 번으로 로그인하거나 처음이면 자동 가입 (`GOOGLE_CLIENT_ID` 가 있을 때만 버튼이 켜진다) |
| 봇 방지 | 아이디 가입·로그인 모두 **Cloudflare Turnstile** 을 화면에 띄우고, 서버가 `siteverify` 를 통과해야만 통과시킨다 |

서버는 Cloudflare Pages Functions + D1(`itda-db`)이다.

| 경로 | 하는 일 |
| --- | --- |
| `GET /api/auth/config` | Turnstile 사이트 키, 구글 클라이언트 ID 같은 공개 설정 |
| `GET /api/auth/me` | 지금 세션의 사용자(비로그인이면 `null`) |
| `POST /api/auth/register` | Turnstile 검증 → 아이디 중복 확인 → PBKDF2 해시 저장 → 세션 발급 |
| `POST /api/auth/login` | Turnstile 검증 → 비밀번호 확인 → 세션 발급 |
| `POST /api/auth/google` | 구글 ID 토큰 검증(대상·발급자·만료) → 기존 계정 조회 또는 자동 가입 → 세션 발급 |
| `POST /api/auth/logout` | 지금 세션만 지우고 쿠키를 비운다 |
| `POST /api/auth/delete` | 세션 확인 → 본인 재확인(비밀번호 계정은 현재 비밀번호, 구글 계정은 `삭제`/`@아이디`) → sessions·users 행과 메일·공지 읽음 기록 영구 삭제 + 쿠키 만료 |

- 세션은 무작위 32바이트 토큰을 `HttpOnly; Secure; SameSite=Lax` 쿠키(30일)로 주고, DB 에는 SHA-256 해시만 남긴다.
- 비밀번호는 Web Crypto PBKDF2-SHA256(무작위 salt, 반복 15,000회 — Workers 무료 플랜 CPU 한도에 맞춘 값)로 저장한다.
  반복 수는 해시 문자열에 함께 남겨 두어, 나중에 올려도 기존 계정은 저장된 값으로 계속 검증된다.
- 요청 제한: 가입 10회/10분 · 로그인 20회/10분 · 구글 20회/10분(IP 기준). 모든 `/api/*` 응답은 `Cache-Control: no-store`.
- 환경변수(Pages 프로젝트 `itda-play`): `TURNSTILE_SITE_KEY`(Text) · `TURNSTILE_SECRET_KEY`(Secret) · `GOOGLE_CLIENT_ID` · `DB`(D1 바인딩).
  Turnstile 위젯 `itda-play-auth` 는 `itda-play.pages.dev` 호스트만 허용한다.


## 메일함 (✉ 받은 · 보낸 · 공지)

홈 오른쪽 위 `✉ 메일함` 버튼으로 연다. 새 메일이나 아직 안 읽은 공지가 있으면 버튼 오른쪽 위에 **빨간 동그라미**가 뜨고,
다 읽으면 사라진다. 로그인하지 않은 게스트는 **공지사항만** 읽을 수 있고, 받은/보낸/쓰기 자리에는 로그인 안내와 버튼이 나온다.

| 탭 | 내용 |
| --- | --- |
| 받은 메일 | 나에게 온 메일 최신순 100통. 열면 자동 읽음 처리(`read_at`), `답장`(받는 사람·`Re: 제목` 자동, `reply_to_id` 연결)과 `삭제` |
| 보낸 메일 | 내가 보낸 메일과 상대의 읽음 여부. `삭제`해도 받은 사람 메일함은 그대로이고, 양쪽이 지우면 행이 실제로 삭제된다 |
| 공지사항 | 누구나(게스트 포함) 읽는다. `ADMIN_USERNAMES` 에 든 아이디로 로그인하면 `공지 작성`과 각 공지의 `삭제`가 보인다 |
| 새 메일 쓰기 | 받는 사람(`@아이디` 또는 `아이디`), 제목(80자), 내용(2000자). 없는 아이디면 안내 문구를 보여 준다 |

서버는 같은 Cloudflare Pages Functions + D1(`itda-db`)이다. 모든 쿼리는 `.prepare(...).bind(...)` 만 쓰고, 모든 응답은 `no-store`,
화면은 서버에서 온 글자를 `textContent` 로만 넣는다(XSS 차단).

| 경로 | 하는 일 |
| --- | --- |
| `GET /api/mail/summary` | 안 읽은 메일·공지 수, 최신 공지 시각, 관리자 여부 (빨간 동그라미 판단용) |
| `GET /api/mail/inbox` · `GET /api/mail/sent` | 받은/보낸 메일 목록 (로그인 필수, 비로그인 401) |
| `POST /api/mail/send` | 메일 발송 (`to`, `subject`, `body`, `replyToId?`). 분당 10통·시간당 60통 제한 |
| `POST /api/mail/read` · `POST /api/mail/delete` | 읽음 처리 · 내 메일함에서 삭제(소프트 삭제) |
| `GET /api/mail/notices` | 공지 목록 (게스트 포함 공개, 로그인하면 읽음 여부 포함) |
| `POST /api/mail/notices/read` | 공지 읽음 기록(사용자별 `notice_reads`) |
| `POST /api/mail/notices` · `DELETE /api/mail/notices` | 공지 작성·삭제 — `ADMIN_USERNAMES` 관리자만, 아니면 **403 forbidden** |

- 공지 작성 권한은 Cloudflare Pages 환경변수 **`ADMIN_USERNAMES`**(쉼표 구분 아이디)로만 열린다. 지금은 비어 있어 아무도 쓸 수 없다.
  Pages 프로젝트 `itda-play` → Settings → Variables and Secrets 에 아이디를 넣고 저장한 뒤 **새 배포**(main 푸시 또는 Retry deployment)를 한 번 하면
  그 아이디로 로그인한 사람에게 `공지 작성`·공지 `삭제`가 보인다(Pages 는 환경변수가 배포에 묶여 있어 저장만으로는 바뀌지 않는다).
- 계정을 지우면 그 사람의 보낸·받은 메일과 공지 읽음 기록도 함께 정리한다.
- 표: `mails`(발신·수신 아이디와 아이디 스냅숏, `reply_to_id`, 읽음/삭제 표시), `notices`, `notice_reads`(사용자·공지 복합 키).

## 보안 · 폭주 방어

계정·메일함 API 는 `functions/_middleware.js` 를 먼저 지난다. 미들웨어는 `/api/*` 의 상태 변경 요청(POST·DELETE …)의 **출처**를 검사해
다른 사이트에서 보낸 교차 요청(CSRF)을 **403 `forbidden_origin`** 으로 막고, 모든 응답(정적 파일 포함)에 `X-Content-Type-Options: nosniff` ·
`Referrer-Policy: same-origin` · `X-Frame-Options: DENY` 를 붙인다(정적 자산은 `_headers` 도 같은 값을 적어 둔다).

- **허용 출처** — 이 요청이 도착한 주소(운영 `https://itda-play.pages.dev`·미리보기 주소), 같은 호스트(http↔https), 로컬 개발(`http://127.0.0.1:*`·`http://localhost:*`),
  환경변수 `ALLOWED_ORIGINS`(쉼표 구분). `Origin: null`(샌드박스 iframe·data URL)은 막는다.
- **헤더가 없는 요청**은 막지 않는다 — 서버·도구·앱 클라이언트용이고, 세션 쿠키가 `SameSite=Lax` + `HttpOnly` 라서 다른 사이트가 끼어들 수 없다.
- **조회(GET)는 출처를 보지 않는다** — 남의 요약을 읽는 것은 무해하고, 그림·링크로도 열리기 때문이다.

| 방어 | 값 |
| --- | --- |
| 요청 본문 크기 | `readJson()` 이 **32KB** 를 넘으면 **413 `payload_too_large`**. `Content-Length` 를 속이거나 없이 보내는 청크도 스트림을 읽다가 끊는다(Workers 메모리·CPU 보호) |
| 쓰기 요청 제한 | `register` 10회/10분·IP, `login`·`google` 20회/10분·IP, 계정 삭제 10회/10분·IP, 메일 발송 분당 10통·시간당 60통, 메일 삭제 120회/분·사용자, 메일 읽음 240회/분·IP, 공지 쓰기/삭제 20회/10분·관리자, 공지 읽음 120회/분·사용자 |
| 조회 요청 제한 | 요약 180회/분·IP, 받은/보낸 메일 150회/분·IP, 공지 목록 150회/분·IP — 화면은 요약을 60초에 한 번만 부르므로 정상 사용자는 걸리지 않는다 |
| 429 응답 | `Retry-After`(초)와 `error: rate_limited` 를 함께 준다 |
| 스로틀 표 청소 | `auth_throttle` 은 요청 25번째·2% 확률로 `window_start` 가 2시간 넘은 행만 지운다(진행 중인 창은 그대로라 제한이 풀리지 않는다) |

권한은 경로마다 다시 확인한다 — 읽음 처리는 `recipient_id = 세션 사용자` 인 행만 바꾸고(`updated` 0), 삭제는 보낸·받은 사람만(다른 사람 메일은 **404**),
답장 연결(`replyToId`)은 본인이 참여한 메일만(아니면 400 `reply_invalid`, 존재 여부도 알려 주지 않는다), 공지 작성·삭제는 `ADMIN_USERNAMES` 만(아니면 403).

메일함 버튼은 메일 API 가 아예 없는 정적 주소(404·405)에서만 숨긴다 — 요청이 몰려 **429** 를 받거나 잠깐 끊겨도 버튼은 그대로 있고 다음 60초 주기에 다시 시도한다.

프런트는 서버에서 온 글자를 `textContent`/`esc()` 로만 넣고(innerHTML 에 값이 들어가는 곳 없음), 로그인·가입·삭제·발송·메일 삭제·공지 작성은
요청이 도는 동안 버튼을 잠가 **연타해도 한 번만** 나간다. 메일함·계정 API 가 **401** 을 주면 화면을 즉시 게스트로 정리하고(`로그인이 풀렸어요` 안내)
상단 계정 아이콘까지 맞춘다. 다른 탭에서 로그인·로그아웃하면 `itda.auth.ping`(localStorage)으로 알려 탭끼리 상태가 어긋나지 않는다.
설정·계정·메일함 창이 열려 있으면 `Enter` 는 뒤의 `대전 시작` 을 누르지 않고, 창을 닫으면 포커스가 그 버튼으로 돌아온다.

## 데이터 다시 만들기

```bash
python3 build/collect_kkuko.py                          # 오픈DB 단어를 build/kkuko-words.txt 로 수집
python3 build/build_data.py                             # 한방/유도/그래프 재계산
python3 build/build_easy.py                             # (필요할 때) 일상 어휘 목록 갱신(명사만)
python3 build/build_data.py --easy-only                 # easy_words.txt 만 바뀌었을 때 stats.json 의 easy 만 갱신
```

사전 원천은 **끄코 유틸리티 오픈DB 목록 하나**다(예전 KKuTu `db.sql` 덤프는 더 이상 읽지 않는다).
`build_data.py` 는 `build/kkuko-words.txt` 를 **손대지 않고** 읽어, 2글자 미만이거나 한글로 시작·끝나지 않거나 한글·숫자·영문자 밖의 글자(자모 `ㅅ` 등)가 낀 표제어만 빼고
`data/words.txt`(732,308개)와 `data/stats.json`(음절 대전 그래프·한방/유도 목록·일상 어휘)을 만든다.
실제 끄투코리아 일반·어인정 방의 기본 룰과 같아서 동사·형용사 사전형(`가다`, `가로질러간다`)과
작품명·어인정 표제어도 그대로 남는다.

`build/collect_kkuko.py` 는 끄코 유틸리티의 공개 오픈API를 시작 음절별로 호출한다.
받은 원본(`build/kkuko-words.txt`, `build/kkuko-raw.jsonl`)은 저장소에 커밋하지 않는다.
